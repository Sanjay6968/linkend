ContentMint:

Frontend User Interface & Architecture Report

Dezai Learners Internship Program

1.0 Introduction and Project Initialization

The primary objective of this project phase was to fully architect, build, and stylize the Frontend User Interface (UI) for ContentMint, an AI-powered LinkedIn content generation platform. The foundation of the application was built using Next.js 16 (App Router) to leverage advanced server-side rendering and routing capabilities. The Turbopack compiler was utilized to drastically reduce local development compilation times.

Initial setup required scaffolding the project using 'create-next-app' and subsequently initializing the Shadcn UI library. Shadcn was chosen because it provides accessible, unstyled foundational components (like Cards, Inputs, and Dropdowns) that do not enforce a strict design language, allowing for complete customization.

2.0 Custom Design System: Earthy Botanical

A critical requirement for this project was to establish a premium brand identity that diverges from standard, generic SaaS aesthetics. To achieve this, an 'Earthy Botanical' color palette was engineered:

  • Background Canvas: #0A0D08 (Very Dark Green/Black)
  • Text & Typography: #DBCAC0 (Pale Sand)
  • Primary Accents: #6F8055 (Sage Green)
  • Secondary Depth: #3E4F32 (Forest Green)
  • Highlights: #C2A3B3 (Mauve)

Implementation Details:
Because Tailwind CSS v4 utilizes a completely modernized, CSS-variable-based engine rather than the legacy 'tailwind.config.js' file, the entire theme was established via a custom @theme block in globals.css. By mapping these specific hex codes to Shadcn's semantic CSS variables (e.g., --color-primary, --color-background), every single UI component installed automatically inherited the premium aesthetic without requiring tedious, manual CSS overrides throughout the codebase.

3.0 Landing Page & Interactive Elements

The Landing Page (/) serves as the marketing entry point. It required high-fidelity interactions to demonstrate product value immediately.

Framer Motion Integration:
A custom <ParticleBackground /> component was developed using Framer Motion to render 25 continuously floating, glowing orbs that utilize the 5-color palette. A significant technical challenge arose during implementation: Next.js threw severe Hydration Mismatch errors because the random X/Y coordinates of the particles were generated differently on the server versus the client.

To mitigate this, the particle generation logic was safely encapsulated within a React 'useEffect' hook, ensuring the mathematical coordinate randomization only executes strictly on the client-side after initial hydration.

4.0 Authentication Flow & DOM Hydration Fixes

The authentication routes (/login, /register, and /forgot-password) were grouped under an '(auth)' route group in Next.js to share a specialized layout that reuses the Particle Background for visual continuity.

Technical Challenge Resolved:
During the construction of the login forms, a critical DOM Hydration error was triggered by Shadcn. The error stated: 'In HTML, <button> cannot be a descendant of <button>'. This occurred because the newest version of Shadcn utilizes @base-ui primitives which handle the 'asChild' polymorphic prop differently than previous Radix UI versions.

To resolve this architectural issue, the 'asChild' rendering logic was entirely bypassed on all form submission buttons. Instead, the native Shadcn 'buttonVariants' utility function was directly applied to standard Next.js <Link> components. This completely eliminated the nested button error while preserving the perfect styling.

5.0 The Core Dashboard Workspace

The primary /dashboard route acts as the AI generation workspace. It is structured using a global persistent sidebar for navigation, applying dynamic styling based on the current 'usePathname' to highlight active routes.

AI Composer & Live Preview:
The workspace features a split-pane layout. The left column contains a large <Textarea> for prompt engineering, alongside native HTML5 date/time inputs for scheduling. The right column renders a 'Live Preview' panel. To provide a robust user experience, Shadcn <Tabs> were implemented to allow the user to seamlessly toggle between viewing a mock LinkedIn Text Post layout and a visual representation of a multi-slide Carousel mockup.

6.0 Drafts Manager & Schedule Features

To support comprehensive content management, two highly specialized sub-routes were developed:

Drafts (/dashboard/drafts):
Implemented a fully responsive CSS Grid layout displaying saved content cards. Each card utilizes a Shadcn <DropdownMenu> component anchored to a 'MoreVertical' icon, providing access to Edit and Delete actions.

Schedule (/dashboard/schedule):
Integrated the complex Shadcn <Calendar> component. The default generic styling was heavily overridden using custom classNames to ensure the active selected dates render in the application's signature Sage Green palette. Adjacent to the calendar, a custom chronological CSS-based timeline was engineered to display upcoming scheduled posts.

7.0 User Settings & API Configuration

The /dashboard/settings page organizes user preferences using a tabbed interface. The most critical component developed here is the API Configuration tab. Because the application will rely on the Groq Llama 3.3 model for AI generation, a secure, masked input field was built for the user to input their personal 'gsk_' API key.

8.0 Conclusion & Backend Roadmap

The Frontend Development phase is officially 100% complete. The application is highly responsive, strictly adheres to the custom design system, and has been thoroughly debugged for React Hydration mismatches.

The next phase of development will focus exclusively on Backend Integration. This includes configuring a PostgreSQL database via Prisma ORM to persist the mock data, building secure Next.js API Routes for JWT session management, and successfully connecting the AI Composer to the Groq API endpoint for live content generation.
